# Catalog-Driven Recommendation Engine — Design Spec

**Date:** 2026-06-13
**Status:** Approved (pending implementation plan)
**Branch (outer wrapper):** to be created off `fix/gis-map-performance` HEAD or `main`
**Repos touched:** inner Laravel repo (engine, tests, MlService) + outer wrapper (notebook, regenerate script, catalog CSV)

---

## 1. Problem

The recommendation output that defenders/evaluators see is weak and indefensible:

- health dominates (~60.53% in the stale live store); top recommendations are almost all health
- functional recommendations are almost absent; healthcare-access recommendations are too low
- APA references, source type, and domain are missing on many recs
- 807 recommendations have no recommendation code
- many recommendations sound clinical (machine-generated free text)
- old disease-action logic is still active

### Root cause (established during brainstorming)

There are two recommendation stores and they disagree:

1. **Live MySQL DB (`osca_db.recommendations`)** — the source of the bad numbers. Seeded before the
   last engine fix and never re-scored; still holds old `DISEASE_ACTIONS`-style clinical text with
   blank codes/APA/domain. (MySQL was offline during investigation; the April `database.sqlite` is an
   even older schema with `category='general'` for all 177 rows — another stale artifact, not used.)
2. **`osca_output/` (notebook export, regenerated by `regenerate_recommendations.py`)** — already
   healthy (health 22.5%, 0 blank codes) but built from the **Python coded-rules engine**
   (`recommendation_rules.py` + `inference_service._build_recommendations`), which uses its own ~28
   internal code scheme (`HEALTH_HYPERTENSION_PHILPEN`, `FUNCTIONAL_ADL_SUPPORT`, `HLT-008` …).

Critically, **`recommendations_list.csv` — the clean, fully-cited 157-entry catalog the user
curated — is not referenced anywhere in code or the notebook.** Its codes (`OSCA_001`, `FUNC_001`,
…) do not match the engine's internal codes.

So the fix is not "patch the rules" — it is **make `recommendations_list.csv` the single
authoritative catalog**, wired into both the notebook and the live system, with auditable triggering
and controlled category balance. Because the `recommendation` text is emitted **verbatim from the
catalog**, the clinical-tone and missing-field problems are eliminated structurally, not by tuning.

---

## 2. Goals & non-goals

### Goals
- `recommendations_list.csv` is the **single source of truth** for recommendation content AND triggering.
- Every emitted recommendation carries: `recommendation_code`, `category`, `WHO_domain`/`domain`,
  `apa_reference`, `source_type`, `service_provider`, `trigger_summary`, `requires_human_validation`,
  `implementation_note` — all non-null, all from the catalog.
- Recommendation **text is verbatim catalog text** (no machine-generated clinical prose).
- Category balance: health hard-capped; functional and healthcare-access both surface; top-3 is never
  all-health for routine seniors.
- The notebook (`osca5.ipynb`) is modified so it can be **re-run to regenerate the catalog-driven recs
  export**, and those recs are applied to the system.
- The live system continues to run **on the MODELS, not the notebook cache**
  (`ENABLE_NOTEBOOK_OVERRIDES=false`). The notebook and live engine share the **catalog CSV as
  content**, not via cache overrides. New seniors are scored live and get catalog-driven recs from the
  same matcher.
- Notebook export and live Flask inference produce identical recommendation logic (single-sourced).

### Non-goals
- No retraining / re-clustering. Frozen `cluster_id` / risk / `composite_risk` from
  `osca_output/predictions/senior_predictions.csv` are reused (per
  `project_clustering_determinism`).
- No switch to `notebook_overrides=true`. The notebook_cache path
  (`ml:repair-notebook-cache --all` + copying CSVs into serving mirrors) is **not** used in normal
  operation and is out of scope here.
- No new ML signals / survey fields. The matcher consumes the senior features the preprocessing
  pipeline already produces.
- No LLM/semantic matching. Triggering is explicit and auditable (tag intersection).

## 3. Architecture overview

```
recommendations_list.csv  (CATALOG: content + trigger_tags + priority_weight)
            │  (shared file, read by both)
            ▼
catalog_recommender.py  (NEW, python/services/)
   ├─ extract_need_tags(senior_row) -> set[str]      # reuses existing feature extraction
   ├─ match(senior_tags) -> [catalog rows that fire] # tag intersection
   └─ select(fired, urgency, risk) -> ranked recs    # capped + needs-first ordering
            │
   ┌────────┴─────────────────────────────┐
   ▼                                       ▼
inference_service._build_recommendations   osca5.ipynb cells 59/60/67
  (LIVE Flask :5002 + regenerate script)     (notebook export)
   ▼                                       ▼
MlService persists -> osca_db.recommendations    osca_output/* exports
```

Both consumers call the **same** `catalog_recommender` against the **same** catalog CSV. There is one
matcher, one catalog, one selection policy.

## 4. Components

### 4.1 Catalog (`recommendations_list.csv`) — two new columns

| column | type | meaning |
|---|---|---|
| `trigger_tags` | pipe-separated string | need-tags that fire this row. Row fires if senior's tag-set ∩ row tags ≠ ∅. Empty ⇒ never auto-fires (e.g. governance meta rows). |
| `priority_weight` | int 1–5 | severity/ordering weight within a category (5 = most urgent). |

All existing columns are unchanged and flow to output. `recommendation` is the verbatim emitted text.

**Need-tag vocabulary** (derived from features the engine already computes — see §4.2). Authored to
cover all 12 categories; examples (not exhaustive — finalized during implementation):

- **Disease** (from `DISEASE_RULE_MAP` keyword hits on `medical_concern`): `dx_hypertension`,
  `dx_diabetes`, `dx_cardiac`, `dx_stroke`, `dx_cancer`, `dx_kidney`, `dx_respiratory`,
  `dx_arthritis`, `dx_mental`, `chronic_disease`
- **Functional**: `frailty`, `adl_difficulty`, `mobility_limited_indoor`, `mobility_limited_outside`,
  `low_independence`, `low_autonomy`, `age_80plus`, `dependency_high`, `caregiver_needed`
- **Sensory / assistive**: `vision_concern`, `hearing_concern`, `dental_concern`, `has_disability`,
  `assistive_device_need`
- **Healthcare access**: `no_checkup`, `healthcare_difficulty`, `transport_barrier`,
  `service_access_low`, `philhealth_gap`, `medical_cost_strain`
- **Financial**: `no_pension`, `financial_household_strain`, `low_income`
- **Social**: `isolated`, `low_participation`, `low_support`, `not_association_member`, `lonely`
- **Mental health**: `lonely`, `emotional_concern`, `dx_mental`
- **Benefits / OSCA**: `benefits_unaware`, `osca_navigation` (broad-eligibility orientation tags)
- **Elder protection**: `abandoned`, `neglected`, `homeless`
- **Household safety**: `unsafe_home`, `fall_risk`
- **Livelihood**: `wants_livelihood`, `productive_capable`

> Coverage requirement: the 37 healthcare_access and 17 functional rows must have tags that actually
> fire on the seeded cohort, so those categories are no longer absent. This is verified by the audit
> (§7), not assumed.

### 4.2 `catalog_recommender.py` (NEW, `python/services/`)

Three pure functions + a cached catalog loader. No global state beyond the cached catalog.

1. **`load_catalog(path) -> list[CatalogRow]`** — loads + caches the CSV; parses `trigger_tags` to a
   set, `priority_weight` to int. One source path resolved like the existing
   `_resolve_notebook_*` helpers (inner `python/services/` copy primary; outer
   `osca_output`/repo-root fallback).
2. **`extract_need_tags(row: dict) -> set[str]`** — **reuses the existing extraction logic** already
   living in `_health_recs` / `_functional_recs` / `_hc_access_recs` / `_financial_recs` /
   `_social_recs` / `_assistive_device_recs` / `_household_safety_recs`: same feature keys
   (`phy_mobility_*`, `func_*`, `sec*` composites, `risk_functional`, `has_pension`, `env_fin_*`,
   `soc_*`, `psych_lonely_r`, `optical_concern`, `hearing_concern`, `dental_concern`,
   `healthcare_difficulty`, `has_medical_checkup`, `lives_alone`, `age`, …) and the same
   `DISEASE_RULE_MAP` keyword scan on `medical_concern`. The thresholds that currently fire each rule
   become the thresholds that emit each tag. **No re-derivation, no new ML.**
3. **`match(senior_tags, catalog) -> list[CatalogRow]`** — every row whose `trigger_tags` intersect
   `senior_tags`.
4. **`select(fired, urgency, risk_level) -> list[rec dict]`** — the **capped + needs-first** policy
   (§5). Returns dicts in the export schema (§6).

### 4.3 `inference_service._build_recommendations` (MODIFIED)

Becomes a thin wrapper: build the senior row → `extract_need_tags` → `match` → `select` → map to the
existing structured-rec dict shape `MlService` already persists. The per-category `_*_recs` functions
and the `recommendation_rules.py` hardcoded **text** library are **retired** (their threshold logic is
absorbed into `extract_need_tags`; `DISEASE_RULE_MAP`'s keyword→meaning mapping is kept but now yields
**tags**, not internal codes). Disease handling no longer emits clinical free-text.

### 4.4 Notebook `osca5.ipynb` (MODIFIED)

- Cells 59/60/67 already delegate to the production engine; they continue to call
  `_build_recommendations`, which now routes through `catalog_recommender`. The `build_recommendation_v2`
  adapter (cell 60) keeps its responsibilities: merge `df_results`+`df_clean` (df_clean supplies raw
  concern TEXT for `medical_concern` keyword matching), remap CRITICAL→HIGH, compute `priority_flag`,
  map to the export schema with citation fields.
- **Retire `DISEASE_ACTIONS`** (the single remaining reference) and any old uncoded path.
- The notebook reads the **same** `recommendations_list.csv` the live engine reads.
- Re-running the recommendation cells (or `regenerate_recommendations.py`) regenerates
  `senior_recommendations.json`, `senior_recommendations_flat.csv`, `recommendation_summary.csv` from
  the catalog, and prints the defense audit (§7).

### 4.5 Live application (MODIFIED minimally)

- `MlService` already persists `recommendation_code`, `domain`, `apa_reference`, `source_type`,
  `trigger_summary` (column widened for `OSCA_001`-style codes). Verify the catalog's extra emitted
  fields (`service_provider`, `requires_human_validation`, `implementation_note`,
  `key_program_tag`) map to existing columns; add nothing unless a field has no home.
- **Re-score to flush the stale store:** `php artisan ml:batch-analyze --force` → all seniors become
  `prediction_source=live_model` with catalog-driven recs. `ENABLE_NOTEBOOK_OVERRIDES` stays `false`.
  Flask services (:5001 preprocess, :5002 inference) MUST be restarted after the code change before
  re-scoring.

## 5. Selection policy — "capped + needs-first"

Given the rows that fired for a senior and the senior's `urgency` (`priority_flag`/composite) and
`risk_level`:

1. **Governance exclusion.** Catalog rows in the `governance` category (the 5 "use as decision support
   only / human validation" meta entries) are **not** ranked per-senior items. They surface as the
   `requires_human_validation` flag already on every rec plus an optional one-line UI/PDF footer.
2. **Health cap.** Keep at most **2** `health` recs for routine seniors, **3** for urgent or HIGH-risk
   seniors. Drop lowest-`priority_weight` health rows beyond the cap.
3. **Ordering.**
   - Urgent / HIGH-risk seniors: lead with health, then highest-`priority_weight` across remaining
     categories.
   - Routine seniors: lead with the **highest-`priority_weight` non-health** need, then interleave
     categories so the **top-3 is never all-health**.
4. **Total cap.** ~8–10 recs/senior (tunable constant); keep highest-`priority_weight` first within
   each category, then across categories.
5. **Determinism.** Stable sort keyed by `(bucket, -priority_weight, recommendation_code)` so output is
   reproducible across runs/devices (consistent with `project_clustering_determinism`).

## 6. Output / persistence schema

Unchanged from the current flat export (no DB migration expected). Each rec dict carries:

```
senior_id, name, barangay, cluster_id, cluster_name, risk_level, critical_priority_flag,
composite_risk, predicted_overall_healthy_ageing_risk, wellbeing_score,
category, domain, priority, recommendation, reason, recommendation_code,
service_provider, evidence_source, apa_reference, source_type, trigger_summary,
requires_human_validation, documents_needed
```

- `recommendation` ← catalog `recommendation` (verbatim).
- `reason` / firing context ← derived from the catalog `trigger_summary` + the specific tag(s) that
  matched (e.g. "Reported hypertension"); `trigger_summary` itself stays the catalog string.
  Firing context lives under a `trigger_context` key, consistent with the current convention.
- `evidence_source` ← catalog `source`; `apa_reference` ← catalog `apa_reference`;
  `source_type` ← catalog `source_type`; `service_provider` ← catalog `service_provider`;
  `domain` ← catalog `WHO_domain`.

## 7. Verification — defense audit + tests

Extend `python/tests/test_recommendation_engine.py` (plain-assert script, exit 0/1) and the
`regenerate_recommendations.py` audit to assert, on the seeded cohort:

- **0** recs with null/blank `recommendation_code`, `apa_reference`, `source_type`, `domain`.
- **Every** emitted `recommendation` string exactly equals a catalog `recommendation` (proves verbatim
  + traceable; proves no clinical free-text).
- `health` share is below a threshold (target ≈ ≤25–30% of all recs) and **no senior** has an
  all-health top-3 when non-health triggers exist.
- `functional` **and** `healthcare_access` are present in output (non-zero), directly refuting "absent
  / too low".
- No reference to retired `DISEASE_ACTIONS` / hardcoded clinical text remains in the firing path.
- Per-category sample dump for manual spot-check.

Live verification: after `ml:batch-analyze --force`, the same category/null-field audit run against
`osca_db.recommendations` matches the notebook export (single-source proof), and the health service
reports `notebook_overrides_enabled=false`.

## 8. Risks & mitigations

| Risk | Mitigation |
|---|---|
| Thin tag coverage leaves functional/HC-access still low | Audit (§7) fails the build if those categories are absent; author tags against the actual cohort, not in the abstract. |
| Code-scheme change (`OSCA_001`…) breaks anything keyed on old codes | Grep for old internal codes in Laravel/views/tests before retiring; column already widened. |
| Catalog path resolution differs notebook vs live | Reuse the proven `_resolve_notebook_*` candidate-path pattern; ship a copy into `python/services/` as primary. |
| Stale live DB persists | Explicit `ml:batch-analyze --force` step + restart of Flask services in the plan; live audit gate. |
| Over-firing (too many recs/senior) | Total cap (§5.4) + per-category caps; audit reports mean recs/senior. |
