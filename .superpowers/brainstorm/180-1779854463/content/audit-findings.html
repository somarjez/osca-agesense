Tier 1 — Critical Breaks usability, accessibility, or design consistency
⚠ Profile form uses a completely different design system
The senior registration form uses raw Tailwind colors (teal-600, slate-200, purple-600) instead of the project's forest/paper/ink palette. A CTA button uses bg-purple-600. Error states use bg-red-50 instead of the alert pattern. Creates jarring visual inconsistency for the most-used data entry form.
profile-survey.blade.php vs qol-survey-form.blade.php
⚠ Flash messages appear as tiny inline badges in the topbar
Success/warning/error session flash messages are rendered as small .badge elements inside the topbar header. They're easy to miss, not accessible (no role="alert"), and visually wrong — a success message looks identical to a data badge. No auto-dismiss, no icon, no positioning.
layouts/app.blade.php:286
⚠ Delete modal uses inline CSS that bypasses dark mode
The "Delete QoL Survey" confirmation dialog uses style="background:#ffffff !important" and hardcoded hex colors. Also uses onmouseover event handlers for hover states. Breaks in dark mode, bypasses the design system, and looks different from every other modal in the app.
seniors/show.blade.php:449–480
⚠ page-subtitle is set on all pages but never rendered
Every page sets @section('page-subtitle', '...') but app.blade.php only renders @yield('page-title') — the subtitle yield is completely missing. This means all page context subtitles (e.g. "275 seniors · Pagsanjan") are invisible. Dead code on every page.
layouts/app.blade.php:262 all 20+ page views
⚠ Modal dialogs lack ARIA roles and focus management
Archive, bulk-archive, and delete modals have no role="dialog", aria-modal="true", or aria-labelledby. Focus doesn't trap inside the dialog. Screen readers won't announce these as dialogs, and keyboard users can tab behind them. Multiple modals are defined per table row — generates duplicate DOM elements for large tables.
seniors/index.blade.php:253 seniors/show.blade.php:444
Tier 2 — High Priority Significant usability, accessibility, or government-readiness gaps
No breadcrumb navigation
Users have no breadcrumb trail to understand hierarchy (e.g. Home → Senior Records → Juan Dela Cruz → QoL Survey). Critical for OSCA staff navigating between senior profile → survey → results → recommendations. GOV.UK and USWDS both require breadcrumbs for multi-level pages.
all show/edit/create pages
Charts have no accessible fallbacks
All Chart.js canvases lack aria-label, role="img", or a text summary below. The doughnut charts have legend: false — legend data only in inline HTML below, not announced to screen readers. The radar chart (Domain Scores) has no textual equivalent at all.
main-dashboard.blade.php surveys/qol/results.blade.php
No reusable page header component
Each page has its own ad-hoc "back button + action buttons" bar with inconsistent spacing, no standard breadcrumb slot, and no uniform subtitle pattern. The seniors/show page action bar, the QoL back button, and the risk report header are all formatted differently.
seniors/show.blade.php:10 recommendations/show.blade.php:6 qol-survey-form.blade.php:11
Emoji icons in recommendations (not accessible)
Category icons (🏥 💰 🤝 🧠 🏨 👁) are used in the recommendations sidebar. Emoji rendering varies across operating systems, can be announced by screen readers in unexpected ways, and looks inconsistent next to the Heroicon SVG icons used everywhere else.
seniors/show.blade.php:503 recommendations/show.blade.php:13
Report pages lack formal government print layout
Risk and barangay reports have no print-specific CSS, no official header (LGU seal placeholder, system name, date generated), no "Prepared by" footer, and no print button. The PDF template uses teal (#0d9488) instead of the system's forest palette. Reports must look official when printed for LGU/OSCA use.
reports/risk.blade.php reports/barangay.blade.php seniors/pdf.blade.php
Senior profile page: 9-column table is too dense
The seniors table has: checkbox + OSCA ID + Name + Barangay + Age + Cluster + Risk + Composite Risk Bar + Actions = 9 columns. On 1280px screens this is crowded. "Composite Risk" and "Risk" columns are partially redundant — the bar already encodes the level. Actions column has 4 visible buttons per row.

Tier 3 — Medium Priority Consistency, polish, and senior-friendliness improvements
No skip-to-main-content link
Keyboard/screen-reader users must tab through the entire sidebar navigation (15+ items) on every page load to reach main content. A hidden "Skip to main content" link at the top is a basic WCAG 2.1 requirement.
Form required fields inconsistently marked
Profile survey uses * asterisks on some fields but not all required ones. No "* Required" legend at the top of forms. QoL survey form doesn't mark required fields at all. Error messages use mixed styles (red-500 in profile-survey, moderate-700 in QoL form).
profile-survey.blade.php qol-survey-form.blade.php
No reusable empty state or loading state components
Each page defines its own empty state ad hoc. The seniors table empty state, recommendation empty state, and QoL survey empty state all use different markup, copy, and styling. No consistent loading skeleton or spinner pattern across pages.
ML status page uses raw dot instead of .status-dot component
The mode banner uses a raw <div class="w-3 h-3 rounded-full"> instead of the established .status-dot component defined in app.css. Minor inconsistency but avoidable.
ml/status.blade.php:13
No mobile navigation (no hamburger menu)
The layout is sidebar-only. On mobile/tablet, the sidebar is always present (just collapsed to icon width). There's no hamburger menu or slide-over drawer for small screens. The topbar search is hidden on mobile (hidden md:block).
layouts/app.blade.php
Topbar date text is too small for OSCA staff
The date display in the topbar is text-[11px] — very small. For OSCA staff who may have varying visual acuity, 11px is below the WCAG recommended minimum for informational text. Several eyebrow labels are also 10.5px.
layouts/app.blade.php:293
Risk wording: "critical_flag" still exposed in senior profile
The $ml->critical_flag variable is checked in seniors/show.blade.php and renders a "⚠ Critical" badge. Per project memory, "CRITICAL" was removed as an official level — this badge should be removed or remapped. Also "Re-run Assessment" language on the button implies clinical action.
seniors/show.blade.php:204
Tier 4 — Polish / Low Priority Nice-to-have improvements once the above are resolved
PDF template uses wrong color palette
The printed PDF report uses teal (#0d9488) for its header border and organization name, while the rest of the app uses forest green (#1a3a31 / #2f6552). Should match the system palette for brand consistency in official printed documents.
seniors/pdf.blade.php:11
Inactive notification bell is still keyboard-focusable
The bell icon button has disabled and cursor-not-allowed but is still rendered in the DOM and in the tab order. Should add tabindex="-1" or aria-disabled="true" with a tooltip explaining it's coming soon.
Help page has a typo: "OSCA AgeS ense"
Line 34 of help/index.blade.php reads "OSCA AgeS ense system" — a space was inserted in the brand name.
help/index.blade.php:34
Recommendation priority numbers ("P1", "P2") need a legend
Priority numbers appear in orange/blue/gray squares but there's no legend explaining what P1–P5 means. First-time OSCA staff won't know if P1 is highest or lowest priority without context.
